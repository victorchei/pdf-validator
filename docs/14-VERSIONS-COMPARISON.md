# Порівняння трьох підходів до оновлення UI

Порівняльний аналіз трьох версій оновлення PDF Validator на основі бренд-буку Житомирської політехніки.

---

## Загальне порівняння

| Критерій | v1: MUI + Brand Theme | v2: Custom CSS | v3: Bootstrap |
|----------|----------------------|----------------|---------------|
| **UI бібліотека** | Material UI 5 (залишається) | Без бібліотеки | react-bootstrap + Bootstrap 5 |
| **Підхід** | Кастомізація теми MUI | Власна дизайн-система | Міграція на Bootstrap |
| **Складність** | Низька | Висока | Середня |
| **Кількість нових файлів** | 7 | ~22 | ~10 |
| **Кількість змінюваних файлів** | 8 | ~10 | ~9 |
| **Видалення MUI** | Ні | Так | Так |
| **CSS Modules** | Для складних стилів | Для кожного компонента | Для складних стилів |
| **CSS змінні** | Так | Так (розширені) | Так + SCSS |

## Переваги та недоліки

### v1: MUI + Brand Theme

| Переваги | Недоліки |
|----------|----------|
| Мінімальні зміни в коді | Найбільший bundle size (~140 kB gzip) |
| Всі MUI компоненти працюють | Залежність від @emotion (CSS-in-JS) |
| Вбудована accessibility | sx props — нестандартний підхід |
| Великий набір готових компонентів | Важко кастомізувати глибше теми |
| React-specific API | Залежність від 5 пакетів |

### v2: Custom CSS

| Переваги | Недоліки |
|----------|----------|
| Нульовий overhead UI бібліотеки | **Найбільші зусилля** на створення |
| Повний контроль над кожним компонентом | Потрібно самостійно реалізувати accessibility |
| Стандартний CSS (variables + modules) | Потрібно писати та підтримувати TreeView |
| Мінімальний bundle size | Менш зрілі компоненти vs бібліотека |
| Без зовнішніх залежностей | Потрібне тестування кожного UI компонента |

### v3: Bootstrap

| Переваги | Недоліки |
|----------|----------|
| ~60% менший bundle vs MUI | TreeView потрібно створити кастомно |
| Знайомий більшості розробників | Менш React-native API (className-based) |
| Потужна SCSS кастомізація | Додаткова залежність: sass |
| Вбудована accessibility | Utility-first може засмічувати JSX |
| Великий набір utility classes | Менше ready-made складних компонентів |
| Легка інтеграція з CSS Modules | Не такий гнучкий як MUI theming |

## Рекомендація

### Якщо пріоритет — швидкість впровадження

**→ v1 (MUI + Brand Theme)**. Мінімальні зміни, максимальна стабільність. Підходить якщо потрібно швидко оновити візуал.

### Якщо пріоритет — повний контроль та мінімальний bundle

**→ v2 (Custom CSS)**. Максимальна гнучкість, але вимагає значних зусиль. Підходить для довгострокового проекту з унікальним дизайном.

### Якщо пріоритет — баланс між зусиллями та результатом

**→ v3 (Bootstrap)**. Золота середина: менший bundle, знайомий API, SCSS кастомізація. Підходить якщо команда знайома з Bootstrap.
